## 作った理由

こんにちは、上海の高校生のZigaoです。毎日Arcを使っていました。The Browser CompanyがArcを12月22日で終了すると聞いて、タブが画面の上に並ぶブラウザには戻りたくないと思いました。試したほかのブラウザは、Chromiumのフォークか、AI中心のものばかりでした。そこで自分で作り、それからずっとメインのブラウザとして使っています。

**なぜChromiumではなくWebKitなのか。** 最初はHeliumをフォークして始めました。ソースは約100 GBあり、ビルドのたびに私のMacで3〜4時間かかりました。これは一人では続けられません。WebKitはmacOSに最初から入っていて、バッテリーとメモリへの負担が軽く、セキュリティ修正もmacOSのアップデートで届きます。それでも、Chromeウェブストアから直接インストールしてChromeの機能拡張を使えます。

**なぜZenやOrionではないのか。** 作り始める前に両方を試しました。どちらもよくできています。ZenはFirefoxの上で動くのでFirefoxの機能拡張を使い、私にはMacのAppらしく感じられませんでした。Orionはそれより近いものの、オープンソースではありません。Arcのように使えて、ネイティブな感触で、オープンソースで、Chromeの機能拡張が動くものがほしかったのです。

## Arcから乗り換える

**Arcの環境をそのまま持ってこられます。** 「ファイル › 別のブラウザから読み込む…」でArcを選ぶと、スペース、固定タブ、固定フォルダ、お気に入り、履歴、パスワード、ログイン状態、機能拡張が読み込まれます。開いているタブも、Split Viewごと読み込めます。タブはクリックするまで読み込まれません。まっさらな状態で始めたいときは「開いているタブ」のチェックを外してください。スペースが複数のArcプロファイルにまたがっている場合は、それぞれのArcプロファイルがZigzagの別のプロファイルになります。

**1Passwordも使えます。** Arcと同じように、Zigzagの中でChromeウェブストアからインストールします。1PasswordのAppと連携して動きます。最初の一度だけ、1Passwordの「設定 › ブラウザ」でZigzagを追加してください。Bitwardenも使えます。

**止められる心配はありません。** アカウントは不要で、Zigzagは私のサーバに依存していません。私が運営しているのはアップデートのフィードと、広告ブロックの短い修正リストだけです。それらがなくなっても、Zigzagは動き続けます。Zigzagが自分で行う接続は、すべて[プライバシー](#プライバシー)に載せています。

## 足りないもの

普段使いのブラウザとして使っていますが、Zigzagはまだ新しく、不具合もあります。Arcユーザが気づきそうな点は次のとおりです。

- MacどうしやiPhoneとの同期はありません。パスワードはiCloudキーチェーンで同期されますが、スペースとタブは同期されません。
- スペースのアイコンはArcから引き継がれません。Zigzagで選び直してください。スペースの色は、最も近いZigzagの色になります。
- EaselとNotesはありません。Boostsは、CSSだけです（「要素を非表示」と「スタイルを編集…」で、サイトごとのスクリプトはありません）。ブラウザにAIは内蔵していません。オンにしたときだけ、AI AppがMCP経由でZigzagを使えます。
- Chromeの機能拡張APIには、まだないものがあります。タブグループAPI、デバッガの設定、Chrome自身のGoogleアカウントログイン（`identity.getAuthToken`）、古いリクエストブロック用のwebRequestです。プロキシの機能拡張は、固定のHTTP、HTTPS、SOCKS5プロキシを設定できますが、PACスクリプトは設定できません。そのため、FoxyProxyの「Proxy by Patterns」モードは動きません。
- EasyListなどの内蔵ブロックリストはZigzagのアップデートで更新されます。自動で更新されるのは、uBlock Originのリストだけです。
- macOS 15.4以降のみ対応しています。

## 仕組み

Zigzagは、`WKWebView` を中心にした約17万行のSwift 6とAppKitでできています。ChromiumもElectronも使っていません。エンジンはmacOSに入っているWebKitなので、Appが小さく、エンジンのセキュリティ修正も私ではなくmacOSのアップデートで届きます。

| 項目 | 仕組み |
|---|---|
| **ページ** | タブごとに1つの `WKWebView` です。しばらく使っていないタブはスリープさせられます。Webビューは解放され、タブはスナップショットと状態を保持し、戻ってきたときに再読み込みします。プライベートウインドウは、永続しないデータストアを使います。 |
| **機能拡張** | WebKitのWeb拡張機能のサポート（`WKWebExtensionController`。macOS 15.4が最低バージョンである理由です）を使います。ZigzagはChromeウェブストアからCRX3パッケージをダウンロードし、署名を確かめて読み込みます。WebKitにないChrome API（履歴、ブックマーク、ダウンロード、通知、サイドパネル、オフスクリーンページ、Webログイン、タブの音声、新規タブページ、ユーザスクリプト、プロキシなど）は、小さなブリッジを通してZigzag自身が応答し、各機能拡張が持つ権限と照らし合わせます。機能拡張が提供する検索エンジン（`search_provider`）は設定の選択肢に加わりますが、自分で選んだときだけ使われます。ネイティブメッセージングで、1Passwordなどの機能拡張のヘルパーAppと接続します。 |
| **サンドボックス** | Webサイトの画像とPDFは、ネットワークにもファイルにもアクセスできない2つのサンドボックス化されたXPCヘルパー、`ZigzagImageDecoder` と `ZigzagPDFRenderer` で読み取ります。壊れた画像やPDFがパスワードやプロファイルに届くことはありません。PDFビューアはヘルパーが描画したページを表示し、AppがサイトのPDFを自分で開くことはありません。 |
| **安全な接続** | 証明書の警告では、何が問題なのかを「詳細」で説明します。HSTSヘッダか、Chromiumのプリロードリスト（同梱、約9万5千件。警告が必要なときだけその場で読み取ります）で安全な接続のみを求めているサイトには、SafariやChromeと同じく、そのまま開く選択肢を出しません。クライアント証明書を求めるサイトには、Safariと同じく、キーチェーンにあるもののうち受け付けられるものが示されます。.p12ファイルをキーチェーンアクセスで開くと追加できます。 |
| **広告ブロック** | EasyList、EasyPrivacy、EasyList Chinaは、SafariConverterLibで事前にコンテンツルールリスト（`WKContentRuleListStore`）に変換し、一度コンパイルしてキャッシュします。有効期限が切れるたびにダウンロードするuBlock Originのリストは、Ghosteryのadblockerエンジンが専用のJavaScriptコンテキストで照合します。ページごとに、そのサイトに必要なスクリプトレットと非表示のルールが、読み込みの開始時に適用されます。 |
| **ダークページ** | Dark Readerのダイナミックテーマとサイトごとの修正を同梱し、専用のスクリプトワールドで動かします。ページにはまずウインドウがダークだと伝えるので、独自のダークテーマを持つサイトはそれを使い、そのままにされます。 |
| **Cookieバナー** | DuckDuckGoのAutoconsentとそのルールを同梱し、専用のスクリプトワールドで動かします。 |
| **パスワード** | キーチェーンの項目として保存されるので、iCloudキーチェーンで同期され、Touch IDで解除できます。パスキーはAppleのブラウザ向けパスキーのエンタイトルメントを通して扱います。自動入力は小さなコンテンツスクリプトで、見えているフィールドにだけ入力します。 |
| **読み込む** | 各ブラウザ自身のファイルを読み取ります。Arcの `StorableSidebar.json`、ChromiumのブックマークとSQLiteの履歴、Safariの `Bookmarks.plist`、Firefoxの `places.sqlite`、Orionの `favourites.plist` と `history` です。Chromiumのパスワードは、macOSが許可を求めたあとに、そのブラウザのキーチェーン項目にあるキーで復号します。 |
| **自分のデータ** | スペース、固定、お気に入りは `Library.json`、プロファイルは `Profiles.json`、開いているタブは `Session.json`、履歴はSQLite（プロファイルごとに1ファイル）に保存し、すべて `~/Library/Application Support/Zigzag` に置きます。書き込みはデバウンスされたアトミックな書き込みで、読めなかったファイルは別に取り分け、上書きしません。 |
| **リーダー** | MozillaのReadabilityをページ内で実行し、Zigzag独自のタイポグラフィで表示します。 |
| **Webアプリ** | Appとしてインストールしたサイトは、`~/Applications/Zigzag Apps` に置かれる小さな独立したAppです。起動のたびにZigzagに処理を渡すので、ページはZigzagの中で、ログイン状態、機能拡張、ブロックの設定を使って動きます。 |
| **アップデート** | Sparkle 2を使い、zigzagbrowser.comからEdDSAで署名されたアップデートを、安定版またはベータ版のフィードで配信します。リリースはDeveloper IDで署名され、公証されています。 |

ソースは機能ごとに分かれています。`Sidebar`、`Tabs`、`Web`、`Extensions`、`Passwords`、`Import`、`Profiles`、`CommandBar`、`Desk`（すべてのタブを一度に）、`WebApps`、`Developer`、`MCP`（AI App）、`Settings`、`Window`、`Design`（Zigzag独自に描いたコントロールとデザイントークン）です。4,000を超えるテストが、読み込み、パスワード、機能拡張、アドレスの処理、履歴、AI App、セキュリティ修正をカバーしています。

## プライバシー

アカウントも、アナリティクスも、テレメトリもありません。閲覧に関する情報が私に送られることはありません。開いたページ以外で、Zigzagが自分から行う接続は次のものだけです。

- **アップデート。** 数時間おきと、Macがスリープから復帰したあとに、Zigzagはzigzagbrowser.comのアップデートフィードを読み込みます。リクエストにはZigzagのバージョンだけが含まれ、システムのプロファイルは送りません。新しいバージョンもそこからダウンロードします。
- **検索候補。** アドレスバーに入力すると、入力中のテキストがCookieなしで検索エンジンに送られ、候補が返ってきます。候補を出すのはGoogle、DuckDuckGo、Brave、Bing、Kagi、Ecosiaで、それ以外のエンジンでは何も送られません。「設定 › 検索」でオフにできます。
- **サイトのアイコン。** アイコンは各サイト自身から取得します。固定タブ、お気に入り、まだ開いていない読み込んだブックマークも同じです。
- **フィルタリスト。** 起動時と、有効期限が切れるたび（数時間おきから1日1回まで）に、uBlock Originのフィルタリストをその公式アドレス（GitHub Pages、Cloudflare Pages、jsDelivr）から、スクリプトレットをGhosteryのCDNからダウンロードします。Zigzag独自のサイト修正の短いリストも、zigzagbrowser.comからダウンロードします。リクエストにCookieは含まれず、自分や閲覧に関する情報も含まれません。
- **機能拡張。** インストールすると、Chromeウェブストアからダウンロードします。起動時に1日1回まで、機能拡張にアップデートがあるかをストアに問い合わせ、その際に機能拡張のIDとバージョンがGoogleに送られます。
- **セットアップ。** ようこそ画面では、Googleのアイコンサービスから数個のサイトアイコンを表示し、プレビューとしてWikipediaのトップページを読み込みます。

翻訳は、Appleのオンデバイス翻訳を使ってMacの中で行われます。不正なWebサイトの警告はWebKit自身のもので、Safariと同じです。パスワードはMacのキーチェーンに残り、自分のiCloudキーチェーンを通してのみ同期されます。「ヘルプ › 問題を報告…」は、送る前に読めるレポートを書き出し、自分で送らないかぎり何も送信されません。Macの「パスワード」リストは、手順の簡単なログを `~/Library/Logs/Zigzag/passwords.log` に残しますが、ログインやサイトは記録せず、Macの外には出ません。Zigzagカードは、アカウントの名前とZigzagを最初に起動した日からMacの中で作られ、画像にはカードに表示されている内容しか入りません。

## インストール

[zigzagbrowser.com](https://zigzagbrowser.com/download)からDMGをダウンロードして開き、ZigzagをApplicationsにドラッグします。Homebrewを使うこともできます。

    brew install --cask zigaowang/tap/zigzag

アップデートは自動でインストールされます。各バージョンの変更点は、[リリースノート](https://zigzagbrowser.com/release-notes)と[CHANGELOG.md](../../../CHANGELOG.md)にあります。

## ソースからビルドする

必要なもの：macOS 15.4以降、Xcode 27以降、[XcodeGen](https://github.com/yonaskolb/XcodeGen)。

```sh
brew install xcodegen
git clone https://github.com/ZigaoWang/zigzag.git
cd zigzag
xcodegen generate
open Zigzag.xcodeproj
```

**Zigzag** スキームを実行します。Debugビルドは「Zigzag Dev」という別のAppとして、専用のデータで動くので、普段使いのZigzagには影響しません。

署名の設定は私のチーム向けになっています。自分のMacでビルドするには、`project.yml` の2か所を変更して、もう一度 `xcodegen generate` を実行します。

- `DEVELOPMENT_TEAM`：自分のチームID（Xcodeの「Settings › Accounts」で確認できます）。
- Debugの `PRODUCT_BUNDLE_IDENTIFIER`：`com.yourname.zigzag.dev` のような自分のものにします。`wang.zigao.zigzag.dev` は私のチームに登録されているためです。

テストを実行します。

```sh
xcodebuild test -project Zigzag.xcodeproj -scheme Zigzag
```
